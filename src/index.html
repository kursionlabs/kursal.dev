A few ideas about resources, grown into a language.

Kursal is built around a checker small enough to run in your head: look at a function and tell, easily, whether it will pass. Its core language, KURS, is explicit enough to check by hand. Kursal, the friendlier surface language, grew out of it. The tools are linear types, brands, capabilities, and that small checked core, and together they have grown into a compiler that builds itself.

Kursal compiles to C. It is not “memory safe by default”: it gives libraries the tools to build resource-safe abstractions, and unsafe exists for the layer beneath them.

A checker small enough to run in your head

KURS, the core language, is explicit enough that you can look at a function and check it by hand: will it pass, and if not, where does it fail? Kursal is the friendlier surface language that grew out of that core. It is more complicated to simulate than KURS, but every Kursal program lowers to KURS, and the small checker verifies the result.

Every block says everything

In KURS, each block states its complete place state: what is full, empty, or lent. You never have to infer state from somewhere else, and a block can be checked on its own. That makes parallel checking possible. The checker runs sequentially today.

Obligations are in the name

A ! on a type means it must be consumed exactly once. You see which values carry an obligation without looking up a definition. The one exception is a type parameter: a T may be linear, and generic code treats it so unless it asks for Copy[T].

Lends are checked per call

A call lends a place and the callee gives it back. There are no lifetimes to infer across function boundaries: a call is judged from the call site and the callee’s signature, never the callee’s body.

Checking is local per function, not per line: whether a line is legal can depend on what the code above it in the same function moved or lent, and on which trait instances exist elsewhere in the program, but never on another function’s body. It is a design test, not a guarantee that every program is easy to read. When a feature would make checking depend on far-away code, that is a reason to cut it. Linearity as a hidden flag became the visible ! for this reason. So does the rule that a struct’s shape can only be built or taken apart in its own module unless it is exposed: whether File!.{ fd: 3 } is legal depends on where you are, not on what other code might do.

Four ideas that fit together

None of them is exotic alone. Each one is there to keep the checker small and local, and the interesting part is what happens when you commit to all of them and see how far a language gets.

Linear types you can see

Files, buffers, locks, and threads must be released exactly once. In C that is discipline. In an affine language such as Rust, a value can be silently dropped and a destructor runs implicitly. Kursal makes “must be consumed exactly once” a property of the type, and writes it in the name.

struct Buffer! declares the type Buffer!. Plain Buffer doesn’t resolve. From any signature you can tell which values carry an obligation, and outside std::io, File!::close is the only method that consumes a File!. The literal can’t be written elsewhere.

Compared with: Linear Haskell puts linearity on function arrows, and ATS pairs linear types with a proof language. Kursal puts it on the type and makes it visible syntax, which is a little ceremonial on purpose.

Forgetting a linear value is a compile error, not a leak.

examples/linear/lib.kur
var h = make_handle(0);
while i < n {
    let old = consume_handle(h);
    h = make_handle(old + 1);
    i = i + 1;
}
consume_handle(h)
error: value 'h' has been moved or is only
       partially available

The loop consumes h and puts a new one back every time around. Call consume_handle(h) twice and you get the error above.

Brands name the memory. Capabilities allow the access.

Aliasing and use-after-free come from conflating two questions: which memory is this? and may I touch it right now? Kursal separates them.

A brand like 'k is a type-level identity carried by Ref[T, 'k]. A Ref can be copied freely and grants nothing. Reading or writing needs a capability for the same brand, such as the linear Exclusive!['k]. Fresh brands come from exists packages, so two allocations can never be confused.

When a container frees or moves memory, it hands itself back under a new brand. Every old view stops type-checking.

Compared with: there are no lifetimes and no Rc<RefCell>. Region calculi and GhostCell-style branding are the closest relatives. Kursal makes that technique the everyday API, not a library trick.

examples/graph/lib.kura cyclic graph, no unsafe
forall 'k.
exposed struct Node {
    id: usize,
    edges: Option[Ref[Edge['k], 'k]],

forall 'k.
exposed struct Edge {
    to: Ref[Node['k], 'k],
    next: Option[Ref[Edge['k], 'k]],

Who frees a graph that points back at itself? Whoever owns the arena, once. Edges are plain Refs.

examples/bad/ref_after_remove_in.kur (trimmed)
let exists 'a. (tag, map, old) = map.insert_in(tag, &cx, 1u32, 10u32);
let found = &map.get_in(&tag, &cx, 1u32);
let exists 'b. (tag, map, removed) = map.remove_in(tag, &cx, 1u32);
match found { Option::Some(r) => r.copy(&tag), ... }
error: brand mismatch: 'b and 'a; 'b was opened at 15:5, 'a at 13:5

The stale r lives under 'a, and the map now lives under 'b. The error names both brands and where each was opened.

Places, not references

Borrowing usually means reference types plus lifetime inference. Kursal has no reference types at all. A parameter marked &x lends a place to the callee, which must hand it back full.

That means you can look at a linear value without giving it up. fn len(&self) -> usize on a linear Buffer! is called as &b.len(), and b is still yours afterward. No borrow type appears in the signature.

Compared with: Rust’s &mut T is a first-class value with a lifetime. Here a lend is a calling convention on a place, checked per call. One call can’t lend overlapping places: f(&x, &x) is rejected with 'x' overlaps another place the same call lends.

examples/mem_counter/lib.kur
forall 'r.
fn bump(&reg: Region![u32, 'r], step: u32) -> u32 {
    let v = &reg.replace(0);
    let placeholder = &reg.replace(v + step);
    v
}

The callee takes the value out, puts a valid one back, and returns. If it didn’t put one back, it wouldn’t compile.

A checked core, so the front end can be wrong

Type checkers in front ends are big and full of special cases, and their bugs become soundness bugs. Kursal lowers everything to KURS, a small, explicit core language where every block states its complete place state: what is full, empty, or lent. A separate, small checker re-verifies the KURS before any C is emitted.

A front-end bug shows up as “front end accepted, checker rejected” rather than as miscompiled code. Because each block’s contract is complete, blocks can be checked independently, a choice made with parallel checking in mind.

We tested this by fuzzing the front end against the checker (21,156 generated and mutated programs, plus about 150 targeted probes). It found 7 distinct gaps where the front end accepted what the checker rejected, including an aliasing hole in f(&x, &x). All were fixed, and later campaigns found none.

Compared with: CompCert-style compilers prove the compiler correct. Kursal re-checks the compiler’s output every time, closer to translation validation. We don’t claim a proof.

What works, and what doesn’t yet

Kursal has not had a 1.0. Expect breaking changes. The ! naming was one, and it was recent.

Works

  • Two compilers, the Python reference and the self-hosted one, kept identical by differential tests.
  • 64 test groups pass, including valgrind on the self-build with 0 errors and 0 leaks.
  • A standard library with files, directories, processes, env, time, threads, Vec, HashMap, arena collections, a TOML 1.0 parser, and formatting.
  • kursal doc, an API doc generator, and 60+ examples.

Rough

  • Linux/POSIX hosted only. Freestanding works if you bring your own runtime.
  • You need a C compiler, and clang dominates build time: about 36 s for the self-hosted compiler’s ~24 MB of C at -O3, against about 4.7 s for the Kursal front end.
  • Diagnostics: name resolution reports up to 20 errors, but later stages stop at the first.
  • No item-level privacy yet, no trait-method forall, no superclass traits, and instances can’t overlap: a generic instance such as forall T. instance Describe[T] rules out every more specific one.
  • No package manager or registry. Packages are directories with a kur.toml.
  • Core output grows roughly quadratically with function size, a price of complete block contracts.
