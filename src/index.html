Language overview

Kursal

A systems programming language with linear values, explicit lending of storage, and capabilities for access to resources. The compiler lowers source to the checked KURS core language, then emits C.

The programming model

Values, places, and authority

The three ideas appear together in real programs. They give the checker a concrete account of what can be copied, what can move, and who may access storage.

01

Copy and linear values

Copy values may be duplicated or discarded; linear values must be consumed once on every path. Named linear types carry a trailing !, and containers can become linear through their contents. Generic code can require Copy[T].

Read about values →
02

Places and lending

A place names storage. A parameter such as &cx lends the caller's place to a function; the callee may work with it and must return the place in a valid state.

Read about places →
03

Brands and capabilities

Brands identify a storage domain at the type level. A reference can describe a location in that domain; a capability supplies permission to read or change it.

Read about access →
04

Representation and unsafe operations

Types are representation-restricted unless exposed. Raw pointer operations and external calls are explicitly marked unsafe, with obligations carried by the code that uses them.

Compilation

From source to executable

Packages are resolved from kur.toml; the frontend infers and lowers the program to KURS. A separate checker validates that core program before the C backend runs. The self-hosted compiler is written in Kursal and is bootstrapped by a Python reference compiler.
